# Draft gaps / limits — no spec approvals

- **FA-1 — Stamp identity migration:** Architecture runner §9 excludes `reference/`, `.selfcheck.json`, `.dockerignore`; existing producer did not use its canonical provenance encoding. New version1 producer/consumer share `problemHash`. Older unversioned stamps fail closed and require actual self-check, never automatic upgrading. No contradictory spec requirement found.
- **FA-2 — Validation inputs versus task/source identity:** Task provenance intentionally excludes reference answers. Self-check freshness additionally binds the reference tree and clean codebase bytes with separately named `inputHash`, satisfying feature/problems §7 revalidation after codebase changes without mislabeling reference or source hashes as task identity. This is local trusted metadata, not cryptographic proof of genuine checks or resistance to malicious stamp forgery.
- **FA-3 — Existing task-hash exclusions:** `problemHash` already excludes `__pycache__` and `.pyc` in addition to spec-listed generated metadata. This refinement does not alter that existing contract; task/source identity and self-check identity remain explicitly distinguished. Hashing follows existing stable-input assumptions, not adversarial mutate-and-restore protection.
- **FA-4 — Conservative stability interpretation (corrected review):** Require step 3 initial solved pass plus all five step 4 repetitions: six solved grades total, in addition to the empty-baseline grade. The earlier architecture-precedence justification for only five solved grades was not justified and is superseded. This stronger interpretation preserves both stated stages without reducing checks or claiming human approval.
- **FA-5 — Required lint:** Existing code silently skipped absent notes/fixWords and missing task text. Version1 success requires the documented inline `fixWords: [...]` front-matter contract and literal, case-insensitive word-boundary checks. This does not invent fix words or modify prompts; unsupported malformed metadata blocks validation.
- **FA-6 — Remaining setup gates:** Selected-fixture admission is not full reported-set setup/failure-gate orchestration, a complete benchmark readiness claim, image attestation of a self-check, or enforcement of every historical runner requirement. Docker/environment changes independent of input bytes and hostile races remain outside this bounded patch. No benchmark fixtures or old evaluation runtime imported.

- **FA-7 — Bounded stamp read, not universal input sandboxing:** Stamp JSON has a 4096-byte ceiling, fd no-follow/nonblocking open, regular-file verification, duplicate-key/schema checks and normalized errors. Existing `problemHash`/tree traversal has no total byte/file/depth limit and trusted-local stable-input assumptions remain; no hostile same-UID race protection is claimed.
- **FA-8 — Clean-base evidence:** A codebase must exist as a real directory before Docker; its canonical tree must remain identical through test and copy. The production discovery command rejects zero discovered tests instead of treating an empty test suite as proof of a valid clean base. These commands were inspected/faked, not executed in a real guest here.

- **FA-9 — Owned paths before mutation:** Simple case-preserving IDs and real directory ancestry are required for selected problems and codebases. All selected inputs are checked before invalidating stamps; generated destinations cannot be symbolic links/special files. This deliberately refuses symlinked checkout/problem roots rather than following them. Existing overlay safeguards remain unchanged; no hostile concurrent replacement protection is claimed.
- **FA-10 — Grading completion versus outcome:** Existing grading swallowed Docker exec failures as failed checks. Version1 self-check now requires `checksCompleted:true`; grader emits/validates a nonce-bound exact exit marker, throws for missing/inconsistent completion, and retains timeout124 as failed checks with `checksCompleted:false`. Marker evidence proves wrapper completion only, not genuine test content/count integrity or adversarial sandboxing. Clean-codebase test-count evidence is separate and enforced by its Python invocation.

- **FA-11 — Generated context policy is a separate contract:** Canonical taskHash continues excluding `.dockerignore`. Producer/consumer now independently require exact `*\n!workspace/\n` bytes through a bounded, no-follow, nonblocking regular-file read before image builds and self-check/eval admission. Missing/tampered policy and Dockerfile-specific overrides are rejected; no broader policy is approved. Fake-boundary sentinel tests verify the contract and no external work on rejection, not real Docker context construction. Stable trusted-local-input/race limits remain.
